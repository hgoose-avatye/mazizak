## 19.0 요약

1. **말랑이는 TPR(젤리)과 슬로우 라이징 폼 두 재질을 모두 1급으로 지원한다** [결정됨].
   - v0.2의 폼 구현은 코드·값·테스트를 그대로 둔다. TPR은 "재질 프리셋 + 모델 분기 3곳"으로 추가한다 [추천].
   - 기획서 §11.1의 "복원 곡선만 다르다"는 틀렸다. 부피 거동, 주름, 표면, 사운드 이벤트 규칙까지 다르다.
2. **콘텐츠 아키텍처는 3층 구조다** [추천].
   - L0: 공용 런타임 서비스
   - L1: 장난감 패밀리별 전용 코어
   - L2: 품목 데이터 프리셋
   - 범용 장난감 정의 언어, 패밀리 간 물리 공유, 범용 파손 시스템은 **만들지 않는다**.
3. **음원은 출처 등급제로 관리한다** [추천]. 매니페스트 하나에 라이선스, 출처, 해시, 녹음 대상, 검증 등급을 기록하고, 빌드 검사로 표기 규칙을 강제한다.
4. 통합 기획서 v0.1과 충돌하는 정책 14건의 수정 문구를 19.4에 제안한다.

## 19.1 말랑이: TPR과 슬로우 라이징 폼

### 19.1.1 현재 상태 [확인]

- **TPR 구현 코드는 저장소 기록에 남아 있지 않다.** 가장 이른 스냅샷(`dcf253e`)부터 이미 폼 모델이다. TPR 동작은 기획서 §6.2·§7.2, 언더댐핑 스프링(`core/spring.ts`), TPR용 합성음(`audio/sfx.ts`)을 근거로 재구성했다 [추정].

  - **셰이더**(`material.ts:40-110`): 2스케일 딤플, 약한 bulge, 압축부가 어두워지는 효과.
  - **사운드 훅**(`toy.ts:194-303`): 모델이 예측한 복원 시간으로 "복원음" 타이밍과 재생 속도를 정한다.
- **함께 발견한 문제** [확인] — 결함 후보이며 별도 승인 대상이다:
  - 합성 폴백으로 넘어가면 폼 이벤트(`sq:recover`)에 TPR용 "탱" 합성음이 매핑된다(`toy.ts:153-157`).
  - CC0 젤 녹음 `compressGel` 5개를 로드하지만 쓰지 않는다. TPR 뱅크의 출발점으로 쓸 수 있다.

### 19.1.3 최소 설계 [추천]

- **원칙**: 폼 경로는 바이트 단위로 그대로 둔다. TPR은 추가 분기로만 넣는다. 추상 클래스나 전략 패턴 계층은 만들지 않는다.
- **데이터**: `SquishyMaterialPreset { id: 'foam'|'tpr', params, recovery: {kind:'foam'} | {kind:'spring', ...}, surface, sound: {bank, rules}, haptic }`.
  - `FOAM.params`는 v0.2 `DEFAULT_PARAMS` 객체 그 자체다.
  - TPR 값은 다른 값에 묻어가지 않도록 **전체를 명시**한다(폼을 튜닝할 때 TPR이 함께 바뀌는 것을 막기 위해).
- **모델 분기 3곳**: 놓기(`release()`), 놓은 뒤 갱신, 늘림·전역 흔들림 복원. TPR일 때만 스프링으로 진행하고 출렁임 횟수를 센다.
- **셰이더**: `#define MZK_FOAM` / `MZK_TPR` 두 프로그램을 쓴다. 폼 캐시 키 `'mzk-squishy-foam-v1'`은 유지한다.
  - **두 프로그램을 미리 컴파일한다.** 키보드 C3과 같은 끊김 위험이 있기 때문이다.
- **사운드**: 뱅크 이름공간을 `sq:foam:*` / `sq:tpr:*`로 나눈다. 이벤트 규칙은 `foamRules`(현행 코드를 이동만)와 `tprRules` 두 함수로 둔다.
- **전환 UX**: `settings.squishyMaterial`, 기본값은 `foam`(v0.2 유지) [미결정: 사용자 확인]. 하단 칩 2개로 전환한다. 홈 카드는 1장 + 재질 칩을 추천한다 [미결정].
- **테스트**:
  - 폼 회귀 잠금: 기존 테스트를 그대로 두고 `FOAM.params`가 `DEFAULT_PARAMS`와 같은지 스냅샷으로 확인한다.
  - TPR: 출렁임 1~3회, 정착 0.3~0.9 s, 60/120 Hz에서 같은 결과, 재누름 시 속도 보존.
  - 전환: 이전 뱅크 소리가 남지 않는다.
- **위험**:
  - TPR이 "고무공 CG"처럼 보일 수 있다 → 투과와 하이라이트 왜곡을 먼저 만들고, 재질별로 실물 영상과 나란히 비교한다.
  - 음수 깊이(튀어나옴)가 과하면 메시가 자기교차한다 → 진폭에 상한을 둔다.
  - 뱅크 2개로 메모리가 늘어난다 → 전환할 때 이전 뱅크를 해제한다.

### 19.2.3 Toy 인터페이스 확장 (최소) [추천]

기존 필드는 유지하고 **선택 필드만** 추가한다. 기존 두 장난감은 수정 없이 컴파일된다.

```ts
interface Toy {
  /* 기존 필드 유지 */
  load?(signal: AbortSignal): Promise<void>;     // 뱅크·메시·셰이더 사전 준비(사전 컴파일 포함)
  dispose?(): void;                               // 뱅크·GPU 리소스 해제 (§18.9 C7)
  variants?(): VariantGroup[];                    // 칩/스와치 목록 → 공통 UI
  setVariant?(group: string, id: string): void;   // setColor/setPreset 대체
}
```

- 현재 `main.ts`는 장난감 생성, 칩, 설정이 하드코딩돼 있다. 장난감 수가 늘어나기 전에 콘텐츠 레지스트리(`ToyManifest { id, family, title, thumb, entry: () => import(...) }`)로 옮긴다.

### 19.2.4 일반화하지 않을 곳 (명시) [추천]

1. 범용 `ToyDefinition` 언어를 만들지 않는다. 데이터는 L2 값까지만 두고, 법칙·이벤트 규칙·상태 머신은 코드로 둔다.
2. 키보드와 변형계 장난감은 물리를 공유하지 않는다(공유는 `Spring` 하나뿐이다).
3. 사운드 이벤트 이름을 패밀리 간에 통일하지 않는다. 엔진과 로더만 공유한다.
4. 왁뿌볼 파손과 크런치 파쇄를 하나의 파손 시스템으로 묶지 않는다.
5. 슬라임을 말랑이 모디파이어로 만들지 않는다.
6. 복원 곡선 에디터를 만들지 않는다. 법칙은 2종으로 고정하고 파라미터만 데이터로 둔다.
7. 공통 경로로 품질이 나오지 않는 품목은 전용 훅(`items/<id>.ts`)을 허용한다.

**추천 조합**
- **키보드**: 초기 4종 이상은 `style-preset`(CC0 편집)으로 빠르게 확보한다. 보유하거나 빌린 스위치를 같은 보드에서 녹음한 세트만 `verified-switch`로 올린다. 구하지 못한 슬롯은 비워 두고, 같은 소리를 이름만 바꿔 늘리지 않는다.
- **말랑이·왁뿌볼·크런치**: 보유 실물을 폰으로 자체 녹음하는 것이 주력이다. 없는 이벤트는 CC0 대체 재질로 채우고, 그레인과 출렁임 타이밍은 합성 스케줄러가 맡는다.
- **CC-BY**는 자동 표기가 동작한 뒤에만 허용한다.

### 19.3.2 등급과 표기 규칙 [추천]

| 등급 | 조건 | UI 허용 | 금지 |
|---|---|---|---|
| `verified-switch` | 해당 모델 실물을 직접 녹음, 실물 증빙, 사람 청취 통과 | 소리 결 이름 + 느낌 보조 라벨, 같은 보드 그룹 안 비교 | 제품명·상표, "똑같은", "재현" |

- 설정 하단 고지문은 등급에 따라 자동으로 고른다.
  - verified: "직접 녹음한 스위치 소리예요. 화면 터치는 실제 키감을 전달하지 않아요."
  - style: "공개 녹음(CC0)을 편집한 ASMR 스타일 사운드이며 특정 제품의 소리를 재현하지 않습니다."

### 19.3.3 사운드 매니페스트 v2 [추천]

기존 `public/sfx/*/*.json`(슬라이스별 원본 구간)과 `CREDITS.md`를 하나의 스키마로 합치고, **CREDITS는 매니페스트에서 생성**한다. 전체 예시는 `research/keyboard-sim/materials-architecture.md` §2.5에 있다.

```jsonc
{
  "schema": 2, "bank": "kb-clicky-a", "family": "keyboard",
  "file": "kb-clicky-a.wav", "fileSha256": "…", "sampleRate": 48000, "channels": 1,
  "sources": {
    "freesound:755222": {
      "kind": "cc0", "license": "CC0-1.0", "author": "forfii",
      "sourceUrl": "https://freesound.org/s/755222/", "retrieved": "2026-11-09",
      "originalSha256": "…", "pageSnapshot": "provenance/freesound-755222.html",
      "subject": { "board": "Anne Pro 2", "switchModel": "Gateron Blue(업로더 표기)", "switchEvidence": null },
      "aiGenerated": false
    }
  },
  "verification": { "level": "style-preset", "sameBoardGroup": null, "humanListened": false },
  "slices": [ { "name": "down_01", "role": "down", "offset": 0.01, "duration": 0.11,
                "src": "freesound:755222", "srcStart": 3.42, "srcEnd": 3.53, "processing": "…", "proxy": false } ]
}
```

**빌드 검사** (`scripts/provenance-check.mjs`, 위반 시 빌드 실패):
1. 슬라이스의 `src`가 `sources`에 있다.
2. CC 계열은 URL, 라이선스, 확보일, 원본 해시를 갖춘다.
3. CC-BY는 표기 문구가 CREDITS와 앱 화면에 실제로 나온다.
4. 허용 라이선스는 CC0, CC-BY 3.0/4.0, 자체 제작뿐이다(NC·ND·SA·Sampling+ 거부).
5. 파일 해시가 일치한다.
6. 메커니즘 라벨이 있으면 등급이 `verified-switch` 또는 `same-board-style`이다.
7. 사람 청취를 하지 않은 뱅크는 출시 빌드에서 경고한다.

- 참고: `sound/recorded-ab` 브랜치에는 이미 라이선스 재검증(페이지 확인 + sha256) 스크립트와 manifest·CREDITS 생성 파이프라인이 있다. v2를 구현할 때 이를 재사용한다.
